Resume Screening System

An LLM-powered screening pipeline that scores resumes against a role description, backed by Postgres and deployed live on Hugging Face Spaces.

Live demo (add link) View repo (add link)

The problem

Screening resumes by hand doesn't scale, and a naive keyword match misses candidates who describe the same skill differently than the job post does. This system needed to score a resume against a role in a way that's consistent, explainable, and stored — not a one-off prompt with no record of how it decided.

How it's built

Resumes and role descriptions are parsed and passed to an LLM that produces a structured score with reasoning, which is written to Postgres alongside the original inputs. The whole thing runs on Hugging Face Spaces, so the pipeline is reachable as a live tool rather than a local script.

What I'd explain if you asked

  • Why the score is stored with its reasoning, not just a number — so a decision can be reviewed later, not just trusted blindly.
  • How the Postgres schema separates raw input (resume, role) from derived output (score, reasoning), so re-scoring with a new prompt doesn't destroy the original data.
  • The tradeoffs of deploying on Hugging Face Spaces versus a dedicated backend host, for this project's scale.
Honest accounting

Vendor benchmark caveat: scoring quality depends on the underlying model's judgment, which isn't independently verified against a labeled dataset yet — treat scores as a strong first pass, not a certified ranking.

What's still rough: no bulk-upload flow yet — resumes are currently submitted one at a time.
