FLASK · GROQ (LLAMA-3.3-70B)

AI Chatbot Backend

A Flask service wrapping Groq's llama-3.3-70b with conversation memory and tool-calling, so the model can act on a request rather than just describe what it would do.

View repo (add link) Ask about this build

The problem

A chatbot that only answers in a single turn isn't useful for much beyond a demo. This backend needed two things a bare LLM call doesn't give you for free: memory across turns, and the ability to actually call tools instead of just describing what it would do.

How it's built

Flask handles the API surface. Each incoming message is appended to a stored conversation history and sent to Groq's llama-3.3-70b, which can invoke registered tools mid-conversation. Tool results are fed back into the model before it produces its final reply, so a single user message can trigger a lookup and a response in one round trip.

What I'd explain if you asked

  • How conversation memory is stored and trimmed, so the context sent to the model doesn't grow unbounded.
  • The tool-calling loop: how the model's tool request is parsed, executed, and the result routed back in before a final answer is generated.
  • Why Groq specifically — inference latency was a real constraint for a conversational product, not an incidental choice.
Honest accounting

What broke: early versions let the conversation history grow without limit, which eventually pushed requests past the model's context window on long sessions. Fixed with a trimming strategy that keeps recent turns and a summary of older ones.

What's still rough: tool-calling currently supports a small, fixed set of tools — adding a new one still means a code change and redeploy, not a config change.
